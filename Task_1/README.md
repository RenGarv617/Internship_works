# Data Analyst Internship — Task 1: Data Cleaning & Preprocessing

## 🎯 Project Objective
The goal of this project is to clean, preprocess, and structure a raw retail transaction dataset (`Online_Sales_Data.csv`) inside a modular folder framework. This pipeline addresses data structural irregularities, handles missing values, eliminates duplicate records, enforces safe data type casting, and validates transactional business logic to ensure data integrity for downstream reporting and analytics.

## 📁 Repository Structure
```text
├── Task_1/
│   ├── source/
│   │   └── Online_Sales_Data.csv          # Raw, untouched input transaction dataset
│   └── cleaned_data/
│       └── cleaned_online_sales_data.csv  # Polished output file auto-generated by the script
├── clean_data.py                          # Automation Pandas cleaning script using safe relative paths
└── README.md                              # Project documentation and storefront
```

## 🛠️ Data Cleaning Steps Applied

### 1. Header Standardization
- Stripped hidden leading/trailing whitespaces from the column headers.
- Converted all column names to standard lowercase format.
- Replaced spaces with underscores (`snake_case`) to maintain database-friendly naming conventions (e.g., `Transaction ID` became `transaction_id`).

### 2. Handling Missing Values (Nulls)
- **Primary Identifier Filtering:** Purged records completely lacking a `transaction_id`. A transaction record without a unique identifier is structurally invalid for database storage.
- **Metric Imputation:** Identified missing numbers in core fields and filled them with baseline defaults (`0` for units sold and `0.0` for unit price) to keep mathematical vectors unbroken.

### 3. Strict Data Type Enforcement
- Converted the `date` string column into proper `datetime` structures. Used `errors='coerce'` safe parsing to turn any corrupted date values into `NaT` (Not a Time) flags instead of letting them crash the pipeline execution.
- Enforced clean numerical types on core metrics, casting `units_sold` to standard integers (`int`) and `unit_price` to floating-point decimals (`float`).

### 4. Duplicate Record Tracking
- Audited the operational primary index to find system sync errors.
- Eliminated redundant data rows by dropping duplicates based strictly on unique `transaction_id` entries, keeping the first valid record.

### 5. Categorical Text Normalization
- Targeted casing inconsistencies across text fields (`product_category`, `product_name`, `region`, and `payment_method`).
- Cleaned string boundaries and uniformly forced the arrays into standard `Title Case`.

### 6. Business Logic & Calculation Audit
- Automatically recalculated the `total_revenue` feature across all metrics as the direct product of (`units_sold` * `unit_price`), rounding values to two decimal places to guarantee flawless financial accuracy.

## ⚡ How to Run the Pipeline

1. Ensure the raw transaction dataset is present in your folder at: `Task_1/source/Online_Sales_Data.csv`.
2. Execute the processing script from your terminal at the root of the repository folder:
   ```bash
   python Task_1.py
   ```
3. Upon execution, the pipeline will programmatically create the missing `cleaned_data/` directory if it does not exist, save the processed file to `Task_1/cleaned_data/cleaned_online_sales_data.csv`, and render a top-5 row preview of the clean data directly in your terminal.
